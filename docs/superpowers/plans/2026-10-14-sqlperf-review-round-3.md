# SQLPERF-T01 Review Round 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make SQLPERF-T01 fail closed per expanded test row, require post-process database ownership reconciliation, and persist a sanitized per-TFM baseline report before the CLI can return success.

**Architecture:** Preserve TRX as the execution authority and add three gates in sequence: row-scoped migration reconciliation, read-only ownership reconciliation after every launched child, and required report export after all passes. The coordinator owns orchestration while row identity, ownership inspection, and report serialization remain focused components with synthetic tests.

**Tech Stack:** C#/.NET 8 runner, netstandard2.0 SQL test harness, xUnit, Newtonsoft.Json, Microsoft.Data.SqlClient.

**Spec:** `docs/superpowers/specs/2026-10-14-sqlperf-review-round-3-design.md`

## Global Constraints

- Preserve `net48`, `net8.0`, and the approved disposable non-production SQL model.
- Do not persist raw theory values, connection strings, database/server names, credentials, machine paths, or server identities in shareable artifacts.
- Post-run reconciliation is read-only and never automatically drops a database.
- Raw TRX, timing JSONL, and ownership journals remain local.
- Run every behavior change through an observed red-green TDD cycle.
- Do not claim T01 complete without the separately approved live SQL gates.

## Review Focus

- Two executed theory rows with aggregate-balanced but row-swapped migration records must fail.
- A testhost that exits zero with a live `Created` database must fail ownership reconciliation.
- A watchdog-terminated child must still invoke bounded ownership reconciliation and retain recovery evidence.
- A report must exclude warm-up, invalid, other-run, and other-TFM timing while ranking sanitized test/class costs deterministically.
- A missing, malformed, or unwritable required report must make `baseline` incomplete.
