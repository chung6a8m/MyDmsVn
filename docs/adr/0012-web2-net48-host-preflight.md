# ADR 0012 — WEB2 net48 HTTP host preflight

**Date:** 2026-10-31. **Decision owner:** Owner-selected WEB2-01. **Status:** dependency/API preflight verified in an isolated net48 probe; IIS/SQL/browser implementation and acceptance NOT RUN. Baseline inspected: `e657d8ddfc6dd4cf8a146ea04325a4dc9f8bd02d`. This refines the HTTP direction in [ADR 0001](0001-local-and-remote-adapters.md) and preserves [ADR 0008](0008-temporary-net8-target-pause.md), [ADR 0009](0009-linq2db-local-net48-persistence.md), [ADR 0010](0010-respawn-fixture-reuse-and-test-policy.md) and [ADR 0011](0011-direct-sales-and-moving-average-costing.md). It changes no shipped project, dependency pin, migration, desktop startup or historical acceptance.

The [server plan](../plans/20261031-003-web2-http-jwt-sales-server.md) owns task status; the [HTTP/auth/wire contract](../design/WEB2_HTTP_AUTH_AND_WIRE_CONTRACT.md) owns storage, cookie scope, TTL, CSRF, claims and wire semantics. Access JWT in localStorage remains the Owner's explicit choice with the documented XSS exfiltration risk. This ADR does not replace it with another storage design. [WEB2 evidence](../evidence/web2/20261031-http-jwt-sales.md) owns executed-candidate results and limitations.

## Decision and verified package candidate

Keep net48 and build a thin IIS/System.Web Web API 2 host in WEB2-02. Use Katana for the OWIN bridge and direct IdentityModel token validation behind a host authentication boundary. Do not select ASP.NET Core or install `Microsoft.Owin.Security.Jwt` merely to obtain JWT validation: that adds a second version-coupled authentication stack. Direct validation must still implement every claim/session/account requirement in the contract; the package alone is insufficient.

The isolated [preflight project](../../tools/Web2.HostPreflight/Web2.HostPreflight.csproj) has exact direct ranges and a [content-hashed lockfile](../../tools/Web2.HostPreflight/packages.lock.json). It is outside all shipped/test solutions, has no project references and does not change the eleven active test projects. Its local `ManagePackageVersionsCentrally=false` keeps exploratory pins out of `Directory.Packages.props`.

### Assembly loading and cookie seam

The probe enables `AutoGenerateBindingRedirects` and `GenerateBindingRedirectsOutputType`. Its generated `bin/Release/net48/Web2.HostPreflight.dll.config` redirects Microsoft.Owin to 4.2.3.0, Newtonsoft.Json to 13.0.0.0 and affected BCL/logging assemblies. **No IdentityModel/JWT redirect is generated in this aligned isolated graph.** A JWT sign/validate test loads SqlClient and OIDC configuration in the same process and checks strong-name presence; it does not prove an 8.16-to-8.23 redirect. This establishes the isolated graph's assembly/API compatibility; opening a SQL connection and Azure AD SQL authentication were NOT RUN. WEB2-02 must inspect the integrated host graph, generate any required redirects and test them in the **deployed Web.config**; a testhost config is not an IIS deployment artifact.

Katana's pinned [SystemWebCookieManager source](https://github.com/aspnet/AspNetKatana/blob/v4.2.3/src/Microsoft.Owin.Host.SystemWeb/SystemWebCookieManager.cs) and [ResponseCookieCollection source](https://github.com/aspnet/AspNetKatana/blob/v4.2.3/src/Microsoft.Owin/ResponseCookieCollection.cs) support Strict, Secure, HttpOnly, Path and Expires. The runtime probe confirms System.Web append/deletion properties and actual OWIN header flags. **Neither CookieOptions nor those writers emit Max-Age.** Therefore using them alone would fail the existing cookie contract. Do not silently substitute Expires for Max-Age.

Select a narrow host-owned refresh-cookie writer in WEB2-04: canonical GUID value, fixed name/Path/flags/no Domain, invariant bounded remaining-lifetime Max-Age and matching clear-cookie scope (Max-Age=0 and expired Expires). It must own the single Set-Cookie write for that cookie, including errors/logout; generic auth/session middleware must not rewrite it. This writer is a planned adapter, not implemented by this preflight. Test its literal response header and browser behavior through IIS. Microsoft [recommends SystemWebCookieManager when running System.Web](https://learn.microsoft.com/en-us/aspnet/samesite/owin-samesite); because that manager lacks the contract's Max-Age, direct header ownership is a justified narrow exception requiring an IIS response-pipeline test for overwrite/duplication. No authentication-cookie middleware or browser ticket is needed for the opaque refresh cookie.

Source/type inspection establishes this graph (all active rows net48):

| Project | Existing dependencies / role |
|---|---|

| SharedKernel; Server.Domain | Domain -> SharedKernel |
| Server.Application | -> Contracts + Domain; MediatR authorization/validation/exception pipeline |

`Desktop.AppCore` remains net8.0-windows PARKED / NOT SHIPPED. The proposed `Server.HttpHost` references Contracts/Application/Infrastructure for composition. It must never call `AddLocalDesktopAdapter`, reference Desktop/WinForms or reuse `LocalDesktopSession`.

- [Application registration](../../src/MyDmsVn.Server.Application/DependencyInjection.cs) supplies scoped anonymous `ICurrentUserAccessor`, rejecting account validation and deny-all permission defaults; [SQL registration](../../src/MyDmsVn.Server.Infrastructure/DependencyInjection.cs) replaces account/permission stores and registers scoped UoW/query services. Replace the anonymous accessor explicitly in each authenticated HTTP scope; do not accidentally retain the TryAdd default or register an actor singleton.
- [CurrentUser](../../src/MyDmsVn.Server.Application/Identity/CurrentUser.cs) is immutable, and the [existing Local accessor](../../src/MyDmsVn.Desktop.Infrastructure.Local/LocalRequestCurrentUserAccessor.cs) initializes once. Its implementation is **internal to Desktop.Local**; copying its session singleton is not an HTTP identity strategy. A separate host accessor should accept an already validated CurrentUser at construction and expose only `Current`.
- Authentication must finish signature/algorithm/key/issuer/audience/time checks, required claims and authoritative active SQL session/account lookup **before** constructing the request's actor and resolving the handler graph. Anonymous login gets CurrentUser.Anonymous. A request retains that actor through all awaits and scope disposal, independent of concurrent requests or later logins. WEB2-02 tests must overlap actors A/B, cancellation and disposal and prove no scope contamination.
- [IdentityAbstractions](../../src/MyDmsVn.Server.Application/Identity/IdentityAbstractions.cs) currently exposes username/password lookup and `IsActiveAsync(userId)`; it has **no session lookup or authoritative user-details-by-sub query**. Introduce the narrow Application-owned auth/session abstraction in WEB2-03/04 with its SQL adapter. Do not use JWT display-name/username claims to fill this gap.
- [AuthorizationBehavior](../../src/MyDmsVn.Server.Application/Security/AuthorizationBehavior.cs) and [PermissionAuthorizationService](../../src/MyDmsVn.Server.Application/Security/PermissionAuthorizationService.cs) continue to check the active actor and current permission snapshot. JWT capability lists never replace these checks. [LoginCommandHandler](../../src/MyDmsVn.Server.Application/Identity/LoginCommandHandler.cs) retains password algorithms/rehash and generic credential denial; successful login today returns CurrentUserDto, not a web session/token.

## Pilot template and configuration boundary

Owner-approved **local template** origin: `https://web2.mydmsvn.test` (default HTTPS port 443; no trailing slash in exact origin comparison). Issuer template: `https://web2.mydmsvn.test`; audience template: `mydmsvn-web2`. These are configuration examples, not deployed DNS, certificates or credentials. Same-origin SPA `/` and API `/api/v1/*`; no credentialed cross-origin CORS. Restrict IIS binding/allowed host to this authority. DNS/hosts mapping, trusted certificate, TLS binding, SPA static fallback and API exclusion from fallback remain WEB2-02 smoke gates.

Use IIS CLR v4 **Integrated** app pool, ASP.NET 4.8 support and explicit startup discovery. [Microsoft's IIS/Katana documentation](https://learn.microsoft.com/en-us/aspnet/aspnet/overview/owin-and-katana/owin-middleware-in-the-iis-integrated-pipeline) excludes Classic pipeline mode; it documents module startup but does not prove this candidate is installed. API auth must execute before handlers; IIS/forms auth must not turn 401 into a login redirect, and denied/error `/api/*` responses must not become SPA HTML.

Trusted proxy allowlist starts **empty**. Pilot connects directly to IIS TLS. Do not trust Forwarded/X-Forwarded-* or a client Host value for issuer/public origin/Secure decisions. A proxy deployment requires a concrete allowlisted proxy/config test before enabling forwarding; no automatic trust by network location.

WEB2-02 configuration must validate required public origin, issuer, audience, bounded lifetimes, active `kid` and allowlisted validation key IDs at startup; cookie/TTL/claims remain contract-owned. Signing material (cryptographically random, at least 256 bits) and restricted web SQL connection are operator-provisioned outside source/package/SPA, readable only by the app-pool identity. Reject missing/weak/unknown-key config; log only safe categories. The maintenance SQL identity is not host configuration. No real key, password, connection string or refresh/access token is recorded here.

## Schema10 -> 11 follow-up inventory and exact admission

Current source recognizes scripts 001–010 and exact schema10, with frozen schema9 support only for the existing restricted maintenance upgrade. No 011 file exists at the inspected baseline. [SchemaCompatibilityPolicy](../../src/MyDmsVn.Server.Infrastructure/Operations/SchemaCompatibility.cs) checks ordered journal names, duplicates, unknown history and artifact sets; [SqlSchemaCompatibilityChecker](../../src/MyDmsVn.Server.Infrastructure/Operations/SqlSchemaCompatibilityChecker.cs) requires `scripts.Count == 10` plus the frozen whole-schema [definition fingerprint](../../src/MyDmsVn.Server.Infrastructure/Operations/SqlSchemaDefinitionFingerprint.cs). Adding tables or changing only the manifest length cannot satisfy this boundary.

WEB2-03 must implement explicit schema11 checks and a **frozen exact10 source validator independent of the new current manifest**. Preserve the existing Schema9/Schema10 fingerprints. Derive and verify a new Schema11 fingerprint on designated non-production SQL. Keep historical 001–010 byte-for-byte unchanged and add 011_WebAuthSessions.sql after rechecking main's next number.

That lock coordinates migrators; it does **not** itself drain ordinary Sales/desktop/HTTP writers. Extend the migration admission deliberately rather than inferring supported versions from `CurrentScripts.Count - 1`. [Schema9MaintenanceValidator](../../src/MyDmsVn.Server.DbMigrator/Schema9MaintenanceValidator.cs) is SQL-login-only, non-contained/restricted-user, requires complete DMV visibility, rejects elevated other writers and verifies no other sessions/requests/transactions/locks; it never changes mode or kills clients. It remains historical 9->10 ownership, not automatic proof for 10->11.

## Verification boundary and recommendation

The [probe README](../../tools/Web2.HostPreflight/README.md) gives exact commands. Final focused run: **24 executed, 24 passed, 0 failed, 0 skipped**: one in-memory WebAPI/OWIN route, one JWT/SqlClient/OIDC assembly-load roundtrip, ten JWT negative cases, two cookie API/header cases and ten int64/decimal string roundtrips from the [canonical numeric corpus](../contracts/web2-v1/numeric-vectors.json). Required-claim/session/account checks, real DI request lifetime, CSRF, refresh persistence/rotation and production cookie writer remain future runtime work; these are not implemented by this probe.

**GO** for WEB2-02/03 implementation using this package candidate and exact follow-up gates. **NO-GO** for IIS/SQL/browser integration acceptance, schema11 deployment, desktop coexistence or production readiness. IIS binding/static/HTTPS/redirect/Web.config/header preservation, browser cookie persistence/deletion and all SQL migration/grant/refresh/concurrency/reset checks are **NOT RUN**. No SQL allocation was created. This ADR closes the dependency investigation, not those runtime tasks.
