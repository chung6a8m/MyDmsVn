# P4 — WinForms desktop foundation

Status: Not started. Depends on P3. Read `docs/ARCHITECTURE.md`, `docs/PROJECT_STRUCTURE.md`, `docs/TEST_STRATEGY.md`.

## Objective

Create a compact, responsive, keyboard-friendly dual-target WinForms shell and reusable ViewModel/UI patterns; UI must only consume Desktop.Application's API client abstractions.

## Task list

- [ ] **P4-T01 / UI dependencies:** inspect actual Bootstrap5WinFormUI and BootstrapSourceGrid TFMs/APIs before references; verify designer/rendering compatibility on net48 and net8.0-windows.
- [ ] **P4-T02 / Shell:** navigation, workspace/document tabs, light/dark theme switch if supported by library, status bar, current user; keep UI and domain state separate.
- [ ] **P4-T03 / MVVM:** CommunityToolkit.Mvvm ViewModel base, observable properties, async commands, cancellation, busy/loading/empty state, centralized notifications.
- [ ] **P4-T04 / API adapters:** register LocalApiClient via host DI to invoke Application, with shared ApiResponse contract. Ensure Desktop.WinForms has no Server.Infrastructure ref.
- [ ] **P4-T05 / Reusable editing controls:** catalog list and editor patterns, lookups, form field error mapping, SourceGrid master-detail prototype.
- [ ] **P4-T06 / Security UX:** disable unauthorized UI actions while retaining mandatory Application authorization checks. Logout/session expiry provide explicit user messaging.
- [ ] **P4-T07 / STA testing:** create/dispose controls under STA, bind/command smoke, catch `DataGridView.DataError`, capture unhandled exceptions without default modal dialogs; timeout/cancel test harness.
- [ ] **P4-T08 / Dual-runtime verification:** run both Windows hosts, compare input appearance/DPI/theme and behavior; document designer compatibility gaps rather than dropping target.

## Exit evidence

Same ViewModel and shared WinForms UI launch through both hosts, test-only local API response displays success/validation, UI smoke tests are bounded and nonmodal. No business CRUD required until P5.

## Avoid

WebView2 or unrelated UI frameworks without requirements, direct DB access in forms, synchronous long-running DB calls on UI thread, modal WinForms exception dialogs in automated tests.
