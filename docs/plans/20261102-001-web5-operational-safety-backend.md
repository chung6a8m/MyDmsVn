## 0. Goals, exit interpretation and strict scope

Make the WEB4 implementation operable under **real host process death, SQL commit uncertainty, operator-assisted reconciliation, journal retention and staging/IIS deployment**, with reproducible test evidence. Keep Sales/Goods Receipt/Inventory and moving-average stock valuation unchanged. Introduce a terminal negative disposition **only when the server can durably prevent any late original request from executing**. **Never change as a side effect:** WEB4 B01 `web4-v1` canonical wire/corpus (48 pinned blobs; backend source `1c603c6ac57e59a3f7b4bc6ca976b2d531c079aa`), SQL business invariants, JWT short access/localStorage decision and HttpOnly GUID refresh, permission keys, required epoch/fingerprint, original Create/Update and Post outcome shapes, server-owned transaction, existing app roles or Desktop exact10. Keep `legacy-web11`/exact11 separate from `web4`/exact12. If protocol/storage must evolve, define a **separately versioned WEB5 extension**; inspect schema012, trigger/constraints and compatibility first. Never silently rewrite a previous migration, pin or fixture. Web principal gets no CONTROL/DDL/journal UPDATE/DELETE. The WinForms CEX-A01–A05 workstream remains independently ACTIVE.

**Explicit exclusions:** activating product same-key resend before B01 safety proof and an approved frontend gate; manual deletion/unlock of UNKNOWN; multi-tenant conversion; wholesale DAL/host rewrite; switch from net48; changing Desktop database; new business modules or inventory costing; automatic offline queue/retry; releasing to actual customers. ## 2. B01 — Real process-crash/Commit evidence (WEB5-01)

**Current facts:** `SqlWebOperationJournal.AdmitAsync/CompleteAsync/FenceAsync` in `src/MyDmsVn.Server.Infrastructure/Operations/SqlWebOperationJournal.cs` operates in caller-owned transaction. Existing `WebOperationJournalTests`, `WebOperationHttpSqlTests`, `WebOperationReadTests` and `WebHostIisExpressTests.Recovery.cs` cover SQL/live-browser but WEB4 expressly lacked an actual operating-system death at the Commit boundary. Existing browser response suppression or OWIN TestServer restart is NOT process-crash proof.

**Implement in test-only infrastructure, not production behavioral knobs:**
1. Record exact mutation and transaction call sites, active SQL connection/transaction lifetime, lock order (epoch → actor/key applock → user/session/permissions → business/stock → journal → commit). Publish a diagram of **pre-dispatch / before SQL Commit / in Commit uncertainty / after Commit but before HTTP response / restart** and who can observe each barrier. Confirm whether `sp_getapplock` uses `LockOwner=Transaction` and timeout 10000ms; do not assume child-process timing makes an assertion deterministic.
2. Create a **separate bounded child host process** in a disposable fresh nonproduction schema12 database with a current-user-only local control channel; injectable hooks limited to a deliberately test-built process/fixture, protected from shipping production binaries. The supervisor records ready/barrier/exit, kills entire owned process tree at requested checkpoint, drains workers, and independently checks SQL from a different connection. Do NOT kill a shared IIS worker or test runner, target a production PID or use unbounded sleeps.
3. Cover six operations (Sales Create/Update/Post, Receipt Create/Update/Post) with precise version/line IDs. For each risk class, use actual SQL oracle on original source, journal, ledger, valuation, stock balances and actor audit. A rollback must leave zero partial effects; a committed outcome must have exactly one authoritative journal and one business effect. For a killed process during SQL Commit, **do not require the outcome to be always committed or always rolled back**; require safe, explicit classification by the fresh SQL oracle and post-restart protected status. Never infer rollback from request cancellation.
4. Run competing workers/connections with the **same actor + operation ID + frozen payload**, including a delayed original and an explicit identical replay, changed-fingerprint 409, revoked permission/epoch change, expired tombstone and multi-warehouse valuation. Test blocked/unblocked lock/fence ordering and finite timeouts. A same-key retry cannot make a second business effect under any ordering.
5. Re-run the selected SQL owners sequentially, verify resource ownership and zero leaked databases/child processes. Keep raw logs/TRX and connection secrets outside Git; publish sanitized source SHA, child-build SHA, actual failure-point observations and oracle counts to `docs/evidence/web5/`.

**Exit B01:** credible externally supervised real process-death + SQL/committed-or-rolled-back oracle; source-reviewed lock semantics; 0 duplicate writes; no unresolved cleanup; completed applicable full SQL-free/SQL suites; independently reviewed P0/P1/P2 findings resolved. B01 alone **does not turn on** product resend or negative-unlock.

## 3. B02 — Authoritative terminal-negative operator resolution (WEB5-02)

**Design gate first:** inspect `src/MyDmsVn.Server.DbMigrator/Scripts/012_WebOperationJournal.sql`, `DatabaseMigrationRunner.cs`, `SqlWebSchemaCompatibilityChecker.cs`, `SqlWebSchema11CompatibilityChecker.cs`, `WebHostOptions.cs`, `Startup.cs`, `SqlWebOperationJournal`, `SqlWebOperationReadRepository`, `SqlWebOperationMaintenance`, HTTP controllers, authorization and the frozen WEB4 corpus. Write a reviewed ADR/protocol decision before touching executable code: reuse existing schema12 `CANCELLED` capability if sufficient **or** introduce append-only migration013, exact-new-schema admission and explicit `web5` host mode; never mutate 012 in place. Provide backward-compatibility matrix for `legacy-web11`, `web4`, Desktop exact10, and proposed WEB5 consumers.

**Expected terminal model:** `COMMITTED` remains immutable business success; `EXPIRED` is historical success without readable result, NOT a negative; `INDETERMINATE`/absent remains unsafe; `NOT_EXECUTED` is a **new authoritative operator terminal state** backed by durable `CANCELLED/DO_NOT_EXECUTE` tombstone that prevents late first arrival and identical replay. Frozen WEB4 `GET /api/v1/operations/{id}` and 48 corpus vectors must not be silently reinterpreted. If a client needs to read terminal negative, create a versioned additive endpoint/DTO or contract expressly agreed with F02; require authenticated actor, epoch and re-derived fingerprint, current grant, bounded result and no cross-actor disclosure.

**Implementation sequence:**
1. Build SQL-free state-machine tests and a real SQL RED test: two independent worker transactions race operator negative close vs original Create/Post under the **identical transaction-owned per-key fence**. One ordering commits business and blocks negative; the opposite commits tombstone first and blocks a late original. Any lock timeout, connectivity fault, missing payload, epoch drift, unknown transaction, actor mismatch or insufficient privilege must produce INDETERMINATE, never CONFIRMED_NOT_EXECUTED.
2. Separate operator identity from application runtime principal. Build exact-key read-only inspection first (current epoch, actor, operation ID, frozen fingerprint, command, target, journal disposition, original result/line/version availability). Avoid exposing full raw draft, passwords/tokens or unrelated actors. Require separately authorized, least-privileged maintenance identity; do not add a generic admin SQL endpoint to the web app.
3. Under a fresh explicit maintenance SQL transaction: verify database/epoch/key and operator authorization, acquire the **same per-key fence** as the original writer, inspect disposition and source effects, insert an immutable terminal negative tombstone **only if no committed/existing effect and safety proof holds**, record an atomic durable audit of operator, correlation, reason and evidence (if schema12 cannot support this, use a new migration), commit once. After commit, verify readback from an independent connection. A missing journal row alone can never authorize terminal state.
4. Modify writer `AdmitAsync` to recognize the terminal negative and reject original/replay deterministically without invoking business logic; preserve the 7-day result cap/tombstone retention. Handle connection loss after operator commit as UNKNOWN until independent readback; no second negative commit attempt with guessed state. EXPIRED/COMMITTED cannot be turned into NOT_EXECUTED.
5. Agree a versioned F02 read-only response/protocol with cross-repo fixtures: positive original Create/Update detail; Sales Post version, Receipt Post no version; terminal negative only as an **operation decision**, not a fabricated business result. Client may release its protected unknown only after an authenticated, exact, durable negative certificate and safe fresh-baseline policy. Older clients remain safe/fail closed.
6. Add capability-denied/actor-change/epoch rotation/permission revocation/result expiry/corrupt fingerprint/duplicate header/unknown-key/racing Commit/exception/rollback/restart security and SQL tests. Review maintenance permissions, triggers and tombstones with an independent reviewer.

### B03 positive COMMITTED-result-unavailable reconciliation (P1-01)

Separate **business success** from **client edit/recovery**. When SQL proves COMMITTED but the original result has expired/unavailable bytes, an operator may close a **support case** as `BUSINESS_COMMITTED_RESULT_UNAVAILABLE` only after independently correlating actor/epoch/key/fingerprint, source header+line IDs, Posted/ledger/valuation/stock/COGS, current authority and a durable case audit reference. The case closure does **not** change journal disposition, fabricate the original result/version, unlock the old local intent or authorize Save/Post/replay. A client can remain PROTECTED after business case closure. If Owner-approved, introduce user-consented scoped **local case/draft archival** preserving minimal support correlation and original SQL tombstone; never treat it as an editable settlement. New editing requires a fresh authorized server baseline/version and explicit user intent (Write-without-Read cannot synthesize this).

Include a seven-day original result-window escalation checklist (detection → triage before expiry where feasible → assigned human owner → permanent case evidence); it is **not** a promised SLA. No premature journal compaction for unresolved cases. Test COMMITTED+original result, COMMITTED/EXPIRED/missing result, no Read grant, wrong identity, IDB/storage failure, failed archival and unresolved support escalation. B03 must demonstrate this flow with real operator tools, not docs only.

**Exit B03:** executable commands with help/tests; attended operator rehearsal on test environment, audit proof, independent before/after SQL data checks and clean owned cleanup. A document-only runbook cannot mark this milestone PASS.
