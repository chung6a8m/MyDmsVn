## Goal and boundaries

Provide one shared, keyboard-friendly and responsive WinForms `LoginForm` + `LoginViewModel` and a deterministic per-host desktop session lifecycle, reused by both `net48` and `net8.0-windows`. Login through the **existing `IIdentityApiClient`/Application Login** path; do not introduce a parallel password/SQL implementation or require P7 HTTP/token infrastructure for Local Mode.

P3 already contains `LoginCommandHandler`/BCrypt. P4 hosts currently render a shell for test/smoke; that is **not** an authenticated production session. Session state and privilege checks must fail closed from first launch.

**Reuse the existing implementations, do not introduce a parallel identity owner:** `IDesktopSession`/`LocalDesktopSession` (generation and current user), `LocalIdentityApiClient` (`BeginAuthentication`/`TrySignIn`), `LocalRequestDispatcher`, `PermissionActionBinder`, `FoundationShellForm` and both hosts' current DI. Their existing session behavior is the starting point; add an explicit per-request authentication snapshot and SQL-backed validation rather than another global/current-user singleton.

## Task list

### P4.1-T01 — Audit contracts and explicit session state machine

- [ ] Inspect `IIdentityApiClient`, `LoginAsync`/`GetCurrentUserAsync`, `CurrentUserDto`, `ICurrentUserAccessor`, `IDesktopSession`, `LocalDesktopSession`, `LocalIdentityApiClient`, `LocalRequestDispatcher`, `PermissionActionBinder` and both host DI composition roots. Document actual gaps before changes; **extend these existing types** and reuse existing generation checks instead of introducing competing mutable session/accessor instances. Keep contracts transport-neutral without changing P7 bearer semantics prematurely.
- [ ] Extend the existing host-scoped session implementation with a documented state machine such as `Unauthenticated -> Authenticating -> Authenticated -> Expired/LoggingOut -> Unauthenticated` and explicit atomic transitions. Session owns immutable authenticated identity (at minimum user ID) and generation/epoch, never the password; lifetime is a **host application session**, not a Windows machine-wide singleton. Define two-login-attempt arbitration and require explicit logout/transition before switching an already authenticated identity; a failed/stale Login must not resurrect a previous session.
- [ ] Make `ICurrentUserAccessor` for an authorized Local request resolve a **request-scoped immutable actor snapshot** (`UserId`, relevant identity fields and admission generation) created at Local API dispatch, **not** the process-wide mutable session at a later asynchronous await. Use an explicit per-request DI/context boundary (or equivalent safe design); no shared mutable identity across requests or host instances. Reject an unauthenticated/expired/stale generation before the request is admitted for authorization. Once admitted and authorized, the P3 `AuthorizationBehavior` actor snapshot remains bound to that request/audit: logout cannot retroactively reattribute or roll back an in-flight write.
- [ ] Decide and document a **configurable Local Mode idle/expiry policy** (monotonic/fake-clock testability, expiry boundary and which user actions reset idle time). Background polls must not count as user activity. Do not silently claim a server-enforced token TTL or automatic HTTP refresh before P7.
- [ ] Define an explicit **SQL-backed session/account validator** in Application/Infrastructure for authenticated `UserId` (existence, `Users.IsActive`, and any actually implemented local-session revocation marker). The current `LocalDesktopSession` accessor hardcodes `IsActive = true` from a `CurrentUserDto`, and `GetCurrentUserQueryHandler` presently reads only this accessor: **this is not revalidation**. Extend `GetCurrentUserAsync`/a dedicated session-validation contract to query authoritative SQL account status; never derive active status solely from the cached DTO. State exactly when validation runs (at least before allowing privileged requests after a validation interval and at explicit refresh/expiry points), how often it can be reused, and how an offline/timeout result blocks privileged work without pretending the password was wrong.
- [ ] Distinguish **account deactivation/session expiry** (clear the session, return a safe `Auth.Unauthorized`/reauthentication outcome) from **role or permission revocation** (live Application permission checks return `Auth.Forbidden` for the affected action and ordinarily retain the authenticated session). `SqlIdentityStore.GetSnapshotAsync` already checks `Users.IsActive`, but a disabled account currently can manifest as a denied permission/403 while the desktop still says signed in; close that gap through central session validation. Do not claim arbitrary server-side session invalidation unless a real revocation record/mechanism is specified.

### P4.1-T02 — Shared compact WinForms Login UI / ViewModel

- [ ] Reusable `LoginForm` with username, masked password, Show/Hide password, submit/cancel, validation/error summary, busy indicator and accessible keyboard order (Enter submits, Esc behaves predictably); use existing Bootstrap5WinFormUI compact styling/theme, DPI/localization patterns, with no new UI framework.
- [ ] `LoginViewModel` using CommunityToolkit.Mvvm async commands and cancellation: prevent double submit, never block UI thread, bound/clear password lifecycle, dispose/cancel work on close. Input validation should mirror public contract without duplicating backend password policy. Clear password controls and release references promptly after completion/cancellation; do not promise zeroization of immutable .NET strings.
- [ ] Provide safe Vietnamese user-facing messages for invalid credentials, disabled/expired session, SQL offline/timeout, unsupported schema and unexpected failures; backend may intentionally map unknown/disabled users to the **same public credential error** to prevent account enumeration. Do not reveal SQL details/stack traces.
- [ ] No password persistence, prefilled administrator credentials, automatic privileged login or credentials in debug logs, telemetry, exception dialogs or screenshots. Never use test/`--smoke-test` switches to bypass authentication in real business flows.

### P4.1-T03 — Host startup, authentication gate and DI scope

- [ ] Both `MyDmsVn.Desktop.App` and `MyDmsVn.Desktop.AppCore` use the same shared startup coordinator. Verify runtime configuration/schema with bounded, localized error handling, then show Login **before allowing access to authenticated shell/navigation**. Reuse existing `DesktopDatabaseStartupCoordinator` preflight and integrate with updated P3.1 registry compatibility; do not run DbUp, permission sync or first-user enrollment from either host.
- [ ] On success set session identity atomically **only after current-user validation against SQL**, then construct/activate `FoundationShellForm`/real workspace with current-user label and permission-based UI actions. On failure, remain unauthenticated, no shell/business API execution. Never treat a cached `GetCurrentUserAsync` echo as proof that the account still exists/is active.
- [ ] Distinguish headless `--smoke-test` of UI wiring from actual production auth: tests can inject a fake session in test-specific DI only, while production bootstrap always requires valid credentials. Avoid global mutable/static identity shared between forms/tests.
- [ ] Treat changing logins on the same desktop process as a new session: reset/recreate user-scoped ViewModels, query caches, lookups, navigation state and messenger subscriptions so prior user's authorized data or permissions never leak. Preserve the existing `FoundationShellForm` session/version-based workspace invalidation and `PermissionActionBinder` guards; close any remaining gaps in in-flight data loads.

### P4.1-T04 — Logout, expiry and concurrency safety

- [ ] Logout explicitly invalidates the session generation, clears session and user-scoped state, cancels pending UI reads/mutations when possible, closes/disables privileged workspace and returns to Login; show success/error UI as appropriate and do not leave hidden authorized screens usable. Reject requests captured but **not yet admitted** under the old generation; cancellation is best effort for requests already authorized.
- [ ] Expired/disabled/invalidated account or local idle session: a 401/`Auth.Unauthorized` (or SQL-backed authenticated status recheck) returns to Login with an explicit reauthentication notice, **not** a silent retry that could repeat a mutation. A 403/`Auth.Forbidden` for a live session/permission change retains the session but denies the specific action. Treat validation SQL outage/timeout as an explicit temporarily unavailable, fail-closed state with retry/reconnect UI, not credential failure or silent fallback to cached `IsActive=true`. Centralize API error mapping for Local and future HTTP modes.
- [ ] At Local dispatch boundary capture the immutable request actor and generation, validate the generation before authorization/admission and execute the Application pipeline with that **same request actor throughout every await** (for example, request DI scope/context); never rebind a queued user-A request to user B's mutable session. On logout/relogin, reject/cancel stale **unadmitted** requests; generation/epoch-check asynchronous UI responses and dispose obsolete controls so A's results cannot update B's screens. Already-authorized in-flight writes by A may commit with A's audit identity; on re-login reload server state rather than assuming cancellation rolled them back. Session state/generation must not be accepted as an auth bypass flag or overwritten by a global static accessor.
- [ ] Avoid password/session material in messenger payloads and logs; clearing UI state must not issue privilege-grant or database-changing commands.

### P4.1-T05 — Dual-runtime automated and manual verification

- [ ] Deterministic ViewModel tests for success, invalid credentials, disabled user public error, validation, cancellation, duplicate submit, network/SQL timeout, busy state, error localization and password clearing.
- [ ] Real SQL (isolated disposable DB) integration: provision first Administrator via P3.1; Login with correct/incorrect credentials; verify `CurrentUser`, role/direct deny, anonymous deny, logout/relogin as another user; direct deny must override Administrator role. Disable/delete a logged-in user directly in SQL and prove the next required account revalidation returns unauthenticated and disables UI/business access; verify `GetCurrentUserAsync` cannot return a stale active DTO. Revoke just a role permission/direct grant and verify `Auth.Forbidden` for that action **without** logging out an otherwise active user. SQL validation failure must block protected dispatch without promoting cache identity to trust.
- [ ] Controlled fake scheduler tests for idle expiry, login/logout/relogin races, two Login attempts, revalidation intervals, disabled-account detection, role/permission revocation, SQL outage/timeout, stale UI responses and failure/cancel during startup. Prove backend denies unauthenticated calls even when UI guards are bypassed and background polling cannot reset idle timeout.
- [ ] Concurrency regression: pause a user-A request **before** Local dispatcher admission/authorization, log out A and log in B, then resume it; assert it is denied/canceled and **never authorized/audited as B**. Independently pause an already-authorized user-A write, switch sessions, and assert any permitted commit/audit retains A's user ID while its late response never updates B's UI. Run parallel Local requests and Login attempts to prove no cross-request/session identity bleed.
- [ ] Safe STA tests for `LoginForm` and shell on **both `net48` and `net8.0-windows`**: control handles, DPI, compact layout, keyboard access, theme, disposal and no `DataError`/`ThreadException`/UnhandledException default modal dialog. Tests must be bounded; never open an unhandled Login prompt in headless CI.
- [ ] Manual smoke from packaged binaries: clean DB -> P3.1 CLI provisioning -> login -> catalog/receipt/stock permission checks -> logout -> another user -> expiry/relogin -> restart. Record environment, target TFM, pass/fail/blocked and screenshots without credentials.

## Exit / acceptance criteria

- [ ] Both production hosts display the actual Login UI and **cannot** reach business features before authenticated session creation; invalid credentials cannot create a session.
- [ ] Shared Login and session components are reusable across both TFMs; extend existing `LocalDesktopSession` and request-scoped Application actor resolution rather than adding a second identity owner. LocalApiClient calls Application, not direct SQL from UI; the new validation store lives behind Application/Infrastructure contracts. No privileges depend on a UI-only check.
- [ ] Logout and session expiry are explicit; SQL-backed account revalidation prevents disabled/deleted accounts from remaining authenticated, while role/permission-only revocations yield 403 for affected operations; no cross-user cache/UI leaks, mutable-actor reassignment or stale response reuse; no silent repeat of mutating requests.
- [ ] With P3.1 Administrator fixture, authenticated P5.1/P5.4 walkthroughs and P6 packaged GUI smoke can run without a test-only production bypass.
- [ ] Update `docs/CONTRACTS.md`/`docs/SECURITY.md` if contract/policy changes, `docs/DEVELOPMENT_PLAN.md` and evidence files after **actual** tests; do not reopen or relabel historical P4 validation as if it covered Login.

## Out of scope

New user/role management screens, password recovery email, "remember me", legacy hash guessing, HTTP Bearer token issuance/refresh/revocation (P7), automated database migrations/seeding on desktop startup, and new business modules.
