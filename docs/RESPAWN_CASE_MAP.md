## Reading the map

Each section names the actual source class/file and project owner; namespaces remain `MyDmsVn.Server.Infrastructure.IntegrationTests`, even in modular owners. A method row inherits its class state/resource contract below and adds any exception. Categories are selection traits, not eligibility. `-` means no Category trait. Every Fact/SqlServerFact has one case. Theory rows are numbered in source order without copying connection strings, password hashes or other raw values; none uses MemberData/ClassData.

At the T00 snapshot, SQL mode was **fresh for every helper allocation**. T01–T04 evidence/additions below supersede that implementation status; the original eligibility inventory remains frozen. Destination `R` means candidate for full application reset profile `APP` after T01/T02 proof, adoption in T03/T04; it does not mean reuse already works. `F` means dedicated fresh allocation in both future comparison modes, with the stated seed/schema exception. `N` means no live SQL, no profile or seed. No original assertion or row is replaced by T00.

No broad ignored-table list is permitted. Child rows include audit/binding -> Users, memberships -> Users/Roles, receipt lines -> headers/Products/Users, headers -> Warehouses/Employees/Users, Employees -> Users, ledger -> Warehouses/Products/Users and balances -> Warehouses/Products. Ledger document/header/line links are logical. Verify all FKs/checks enabled and trusted, including a future cyclic graph, after reset. Reject unexpected schema/object/permission/trigger changes before using cached metadata.

All 13 mutable identity columns use `IDENTITY(1,1)`: Users, Roles, UserRoles, RolePermissions, UserPermissions, Products, Warehouses, Employees, Customers, GoodsReceipts, GoodsReceiptLines, StockLedger, SecurityAuditEvents. SystemSecuritySettings uses a singleton key; StockBalances uses a composite key. T01 must prove never-inserted/populated/repeated-reset behavior. `dbo.GoodsReceiptNumberSequence` is bigint, starts at 1, increments 1, min 1/max 9999999999, NO CYCLE; reset it explicitly in APP test SQL to restart at 1. No rowversion/time rewind is assumed.

`007_Inventory_Stock.sql` creates `dbo.TR_StockLedger_AppendOnly`, `INSTEAD OF UPDATE, DELETE`, unconditionally throwing 51000. Even empty-ledger DELETE invokes it. After positive allocation/schema ownership checks, only this exact trigger may be disabled by APP, restored in finally and definition/enabled-state verified before body admission. Test empty and populated resets; restore/reset/seed/drain failure poisons the fixture. Production scripts remain untouched.
