# MyDmsVn WinForms UI

Use the active task and its scope, not historical acceptance, to select work. Read `AGENTS.md`, `AI_CONTEXT.md`, `docs/plans/README.md` and the selected task; then `docs/design/BUSINESS_COMPACT.md`, the applicable module specification, `docs/design/INDEPENDENT_UI_LABS.md`, and relevant runbook and `docs/TEST_POLICY.md`. The [active roadmap](../../../docs/plans/20261027-001-business-compact-and-independent-ui-labs.md) owns UIL task state. The [candidate inventory](../../../docs/evidence/ui-labs/20261027-business-compact-and-independent-ui-labs.md) records the inspected baseline and pending decisions, not acceptance.

Before editing, inspect the actual app call sites, project graph and recursive vendor gitlinks. Read the pinned WinFormsKit component contracts and implementation; map each affected surface to its public capability, including existing toolkit controls. Record a specific capability/compatibility reason and verification for any interactive native/custom exception under BC-08. Preserve app ownership of drafts, navigation, authorization and session identity, and vendor ownership of composite internals. Do not assume a gallery profile or proposed helper is a public API.

Use the correct module Lab with production controls and fake ports once the relevant launcher exists; until then identify the existing mixed host and its limits. Establish product theme/typography, actual workspace client geometry and DPI, dialog ownership, native keyboard/caret and lifetime effects. Do not claim a direct Security launcher or parity before implementation. Preserve the active task's dependencies and do not use the Lab to expand its scope.

Run focused, nonempty-discovered checks for actual changed boundaries under the test policy; serialize GUI work and record native observations separately from screenshots. Record candidate source/test/vendor revisions, environment, physical scale and DeviceDpi, outer/client/content geometry, fixture/actions, component choices, results, findings and limitations in the selected evidence. A docs-only task needs diff/link/status/encoding review, not SQL or GUI. Route the native candidate to the Owner gate named by the selected task; a build, screenshot or historical decision does not approve it. Product-host verification follows only where the active task admits it. Report what was actually verified and what remains open.
